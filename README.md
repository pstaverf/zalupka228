# zalupka228

## Запуск

Python 3.10 или новее:

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python mines.py
```

При обновлении переносите вместе `mines.py` и `localization.py`. Все переводы встроены напрямую в `localization.py`, без внешних сервисов и дополнительных JSON-файлов. Текущие параметры запуска и настройки сохранены.

## Языки

В личном чате: `/settings` → «🌐 Язык» или команда `/language`. Доступны русский (`ru`), английский (`en`), украинский (`uk`) и казахский (`kk`). Выбор сохраняется в `bot_user_settings.language` и применяется сразу без перезапуска бота.

Локализация охватывает меню, кнопки, игровые экраны и справку, баланс и переводы, банк, P2P, чеки, промокоды, события, рефералов, подарки, задания, административные экраны, ошибки и уведомления. Личные уведомления переводятся на язык получателя.

Никнеймы, имена, комментарии и причины блокировок остаются в исходном виде и экранируются через `html.escape`. Названия валют, технические идентификаторы и команды не переводятся. В примерах используются поддерживаемые команды: `/transfer` для mCoin, `/send` для MP; прежние русские варианты сохранены.

Банк и P2P распознают операции по стабильным данным кнопок; для прежних текстовых сообщений сохранено распознавание заголовков на всех четырёх языках. Правила игр, коэффициенты, финансовые расчёты и SQL-запросы не изменены.

## Изменение переводов

Переводы шаблонов сообщений (`CATALOG`, где русский фрагмент — ключ, а `en`, `uk` и `kk` — его переводы) и служебные интерфейсные метки (`INTERFACE`, по 53 ключа для каждого из 4 языков) находятся непосредственно внутри `localization.py`. Нельзя удалять или изменять параметры вида `{0}`, `{1}`. Динамические значения подставляются после перевода, поэтому пользовательский текст не обрабатывается словарём.

После изменения словаря выполните тесты и перезапустите бота.

## Аудит-лог действий администрации

Все успешно зафиксированные административные изменения записываются в таблицу очереди `admin_audit_outbox(id, message, created_at)` и доставляются фоновым воркером `_admin_log_worker()` в чат `-1004473332427`:

- **Настройка чата `-1004473332427`**: добавьте бота в супергруппу или канал с ID `-1004473332427` и выдайте ему право на отправку сообщений.
- **Семантика доставки at-least-once**: запись в `admin_audit_outbox` создаётся только после успешного `commit` основного изменения, а удаляется из очереди (`DELETE` + `commit`) только после подтверждённой отправки в Telegram. При сетевых сбоях, перезапуске бота, отмене задачи или ограничении `TelegramRetryAfter` запись сохраняется в SQLite и будет повторно отправлена в строгом порядке FIFO с интервалом `ADMIN_LOG_INTERVAL = 3.1` с и экспоненциальным backoff (`1..300` с), поэтому в редких случаях обрыва соединения после приёма сообщения серверами Telegram возможна повторная доставка одного и того же лога (at-least-once), но потеря подтверждённых событий исключена.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m py_compile mines.py localization.py
.venv/bin/python tests/benchmark_performance.py --iterations 100
```

Тесты проверяют полноту словаря, HTML и параметры шаблонов, сохранение и переключение языка, игровые варианты и коэффициенты, валюты, банковские и P2P-ответы после смены языка, язык уведомлений и изоляцию параллельных обработчиков. Для тестов используются временные базы SQLite и подменённые обращения к Telegram; настоящие платежи и сообщения не отправляются.
